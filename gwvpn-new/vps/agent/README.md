# GWVPN AWG Agent — персональные пиры для каждого пользователя

## Проблема, которую это решает

Раньше **все** пользователи приложения получали один общий клиентский конфиг
(`my_phone.conf`): один `PrivateKey`, один туннельный IP. Для сервера WireGuard
все юзеры были одним peer'ом. Из-за встроенной в WireGuard защиты от
replay-атак (монотонный timestamp в handshake на каждый peer) одно устройство
со сбитыми вперёд часами **навсегда блокировало подключение всем остальным** —
до перезапуска `awg-quick@awg0`. Поэтому серверы «умирали» через 1–2 недели.

Теперь каждый `userId` получает **собственный peer** (уникальные ключи и IP).
Приложение обновлять не нужно — оно как и раньше берёт поле `config` из API.

## Состав

| Файл | Назначение |
|---|---|
| `gwvpn_awg_agent.py` | Агент: HTTPS-сервис выдачи пиров + cleanup-режим |
| `setup_agent.sh` | Установщик: подсеть /16, токен, TLS, systemd, UFW, cron, регистрация в API |

## Установка (на каждый AWG VPS)

```bash
# скопировать оба файла на сервер, затем:
sudo bash setup_agent.sh --api-ip=IP_ВАШЕГО_API_СЕРВЕРА
```

Порядок для нового сервера: `install_awg.sh` → `upd_awg.sh` → `setup_agent.sh`.
Для уже работающего сервера достаточно одного `setup_agent.sh`
(перезапуск awg при расширении подсети ≈ 1–2 сек простоя).

**Важно:** сначала задеплойте обновлённый API (ветка per-user-конфигов),
иначе шаг регистрации агента вернёт ошибку (скрипт можно перезапустить).

## API агента

- `GET /v1/health` — статус, число пиров. Заголовок `X-Auth-Token` обязателен.
- `POST /v1/peer` `{"user_id": "..."}` — идемпотентно создаёт peer
  `u_<sha256(userId)[:16]>` и возвращает `{"success":1,"name":...,"config":"<base64>"}`.

## Эксплуатация

```bash
systemctl status gwvpn-awg-agent      # статус
journalctl -u gwvpn-awg-agent -f      # логи
awg show awg0 | grep -c '^peer'       # число активных пиров
cat /etc/gwvpn-agent/agent.env        # токен/настройки
```

Чистка пиров без handshake более 30 дней — ежедневно в 04:30
(перед удалением кэш конфигов в API инвалидируется; если API недоступен,
чистка откладывается). Лог: `/var/log/gwvpn-awg-cleanup.log`.
